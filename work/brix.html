Overview

An agent-driven recruiting system built for modern hiring teams.

Brix replaces filtering and guesswork with two AI agents: one helps recruiters define an ideal candidate profile, the other searches against it and learns from their feedback.

Business Goal

Build an AI agentic talent search tool — aligning product growth with AI transformation.

The business goals were to:

  1. Expand the user base by making Talent Search a standalone AI agent, lowering the barrier for recruiters and agencies and opening a path to the full ATS and EMS suite.
  2. Reposition the platform as AI-native by embedding agentic workflows into recruiters' daily work.
Uncovering the Problem

Candidate criteria were treated as something to execute, not discover.

Two pain points ran through every recruiter workflow: defining what “ideal” means is slow and subjective, and results need heavy manual review before anyone can act.

Right observation, wrong problem. Search was a rule-based filter: you had to know what you wanted before you could begin. Two attempts to fix that failed on the same assumption.

01 AI-Assisted Matching

The direction already in flight. It parsed job descriptions, suggested filters and ranked by similarity — all of which made the input easier to produce.

It did not move the judgement. Recruiters still had to decide whether a direction was right, and kept running the same job description again.

Running the same JD twice is the tell: if the requirement were settled, there would be no second search.

02 Deep Search & Auto Enrich

The opposite bet, and the one leadership favoured: remove the manual work. Expand the search space, run variants in parallel.

Engineering put a full run at twenty minutes. Worse than slow: for twenty minutes a recruiter could neither steer nor add what they knew — and still could not tell why a candidate had surfaced.

Automation cannot rescue a goal that was never defined. It answers the wrong question faster, and locks you out while it does.

01 Requirements were rigid once defined

Requirements were treated as configuration — keywords, filters, a job description — and hardened once a search began.

02 Results were how people worked out what they wanted

Recruiters used search output to work out their own thinking. The results were not the answer; they were the instrument for arriving at the question.

03 More automation meant less to steer by

More automation meant less visibility into how decisions were made, and less to steer by.

Both attempts treated what we are looking for as a known input. It is not one — recruiters only get there by looking at results. That is why twenty silent minutes were fatal, and why easier filters never helped.

I proposed splitting the product in two. Each dead end handed us a question: the first became defining intent, the second making the first ranking answer to it.

Product Solution

Connecting the mapping and search agents in a continuous learning loop

The two agents run as a loop: Mapping structures intent, Search learns from results to sharpen the next match.

Mapping Agent

How might we use AI to help recruiters define and refine Ideal Candidate Profiles?

Answering the first dead end. The agent takes a rough job description and returns a structured, editable profile.

In early 2025 no single generated profile was worth trusting. Rather than chase accuracy we could not guarantee, the agent proposes three at once, reasoning visible as they draft. Recruiters pick a direction, revise it, and that version becomes the basis for search.

Search Agent

How might we make the first candidate search result more accurate and aligned with intent?

Answering the second dead end. Early results missed not because the data was wrong but because intent was never fully captured.

Recruiters tune the results before the full search runs. Rating an initial shortlist teaches the agent what good looks like for this role.

Design Details

The small decisions that make an agent feel trustworthy.

There were no patterns to borrow. Each came from watching recruiters not trust the thing. The industry has since landed close to all of them — which says the reasoning held, not that we were early.

01 The agent sits on the left

Chat was the pattern then, and it docked to the right — where a help widget goes, beside the real work. Moving the panel to the left changes what it is: the place you start, with the document to its right as the thing it produced. Same components, a different claim about who is doing the work.

02 Showing the work, not just the answer

Doubt is not answered by a better result but by seeing how the result was reached. The agent streams its reasoning and keeps a version history.

03 Two agents, one conversation

A first-run introduction names both agents; after that nobody chooses — the system reads intent and calls the one the request belongs to.

04 Nothing was taken away

Recruiters who trusted the old way kept it: upload a job description, paste filter terms, or type requirements straight in. The agent is a faster path through the same door.

Design System

A scalable conversational design system for agent-driven interfaces.

As Brix AI took on more responsibilities in the recruiting workflow, we needed a scalable design system to unify the interface patterns, ensuring consistency in user experience and efficiency in development.

The system defines how the agent communicates, acts, and delivers results — from chat primitives to structured task outputs.

Thoughts After Launch

01 Put Human Intervention Where It Has the Highest Leverage

The argument about automation is usually about quantity — how much to hand over. The useful question is where. Picking one draft of three takes seconds and decides an entire search.

02 Designing for Cognitive Ease

Familiar, scannable formats with the relevance spelled out did more for confidence than a better answer would have.

03 Systems Need Clear Decision Boundaries

Naming what the agent would not do removed more doubt than raising its accuracy did, and made the workflow easier to scale.

Looking back

Agentic transformation was widely read as “make it conversational.” People wanted natural language for some tasks and direct controls for others. The goal was never to converse.
