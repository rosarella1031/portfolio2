把「有光源」翻译进浅色

Bella 那个背景里没有噪点、没有纹理、没有滤镜 —— 全部是渐变。真正在起作用的只有一件事： 页面有一个光源。底色 #0a0a0a（不是纯黑，留出往上提的余地）、主图背后一团 blur(40px) 的蓝色光晕、图片底边用 scrim 溶进背景、顶边一道 4% 的白色高光。

这套东西不能直译。暗色里光晕是加光；浅色里你没法往白上加光，只能减光 —— 直接翻过来就是一块脏印子。 浅色的等价物是把关系倒过来：页面不再是发光的底，而是被照亮的纸。光源还在，但表现为纸浮起来、影子落下去。

这里有个顺带的好处。你的产品截图平均色是 #FCFCFD，几乎纯白 —— 放在纯白页面上，物理上不可能有边界（对比 1.025）。现在的做法是给图配更深的底 #F8F8F8， 结果图是陷进去的。Bella 的结构正好相反：媒体浮在页面之上。

0 · 现状 页面 #FFFFFF · 图块 #F8F8F8 图比页面深 —— 陷进去
--bg: #ffffff; .img-block { background: #F8F8F8; }

截图四周的白和图块的 #F8F8F8 差 1.009 —— 等于没有边界。图糊在底上， 整块看起来发平。深浅关系也是反的：内容比容器暗，等于把主角压进背景里。

A · 抬纸 页面 #F7F5F0 · 媒体 #FFFFFF + 柔影 最小改动，改两个值
--bg: #F7F5F0; /* 页面退一档，让出上方空间 */ .img-block { background: #fff; box-shadow: 0 1px 2px rgba(60,50,40,.05), 0 10px 28px rgba(60,50,40,.07), 0 28px 56px rgba(60,50,40,.05); }

深浅关系正过来了：内容比页面亮。注意分离感几乎全部来自影子，不是来自颜色 —— 白卡和 #F7F5F0 只差 1.09，靠色差是撑不住的。三层影子里最外那层（28px 56px / 5%）负责"浮"， 最里那层（1px 2px）负责"实"，少了任何一层都会塌。

B · 抬纸 + 光晕 A + 背后一团 blur(40px) 的暖色影 她那团蓝光的浅色对应物
.bloom { /* 放在媒体下面一层，比媒体大一圈、往下偏 */ position: absolute; left: 6%; right: 6%; top: 12%; bottom: -6%; filter: blur(40px); background: radial-gradient(closest-side, rgba(176,163,140,.50), rgba(176,163,140,.16) 55%, transparent 78%); }

同样是 blur(40px)、同样是 closest-side 的径向渐变、 同样比媒体大一圈往下偏 —— 只是颜色从"加光"换成了"落影"。 效果是媒体不再是贴在页面上的一张纸，而是悬在页面上方一点点。 颜色取的是你 --border #DDD8CF 的同一支暖灰，所以不会脏。

C · 溶边 不要框，底边 mask 进页面 她的原结构 — 只能用在 hero
.hero-media { mask-image: linear-gradient(to bottom, #000 62%, transparent 100%); border-radius: 10px 10px 0 0; /* 底边没有边，就不需要圆角 */ }

这是她实际用的做法：图不结束，只是消失。页面读起来是连续的一整片，而不是"一段字、一个方块、又一段字"。 但这条只能给 hero 用。正文里的图溶掉底边就是吃掉内容 —— 她自己也只在首屏这么做，往下的图全是规规矩矩的方块。

细节 · 顶边高光 她用 rgba(255,255,255,.04) 0 → 14% 浅色里几乎无效
不加
加了（已放大到 90%，仍然看不出）

这一条直接放弃。顶边高光的原理是"光从上面打下来，最先照亮上沿" —— 在近黑的底上 4% 的白就够，在近白的媒体上你把它拉到 90% 都还是白加白。 浅色里承担同样叙事的是影子的方向：把 box-shadow 的 y 值全部设正，光就在上方，不需要再画高光。

让它活起来

她整个页面里唯一在动的背景元素是一条 tmSweep：156px 宽、rgba(255,255,255,.035) 的光带， 16 秒横扫一次，其中最后 30% 停着不动。光源在缓慢移动 —— 就这一条。

这件事浅色里反而更好做：她只能用 3.5% 的白（再高就脏），而影子在浅底上是清清楚楚可读的。 下面四种都在动，鼠标划过去 / 滚动看看。

D · 光源跟着光标 pointermove → 光晕位置 ← 把鼠标移到图上
stage.addEventListener('pointermove', e => { const r = stage.getBoundingClientRect(); stage.style.setProperty('--mx', (e.clientX - r.left) / r.width * 100 + '%'); stage.style.setProperty('--my', (e.clientY - r.top) / r.height * 100 + '%'); }); .bloom-track { background: radial-gradient(closest-side at var(--mx) var(--my), …); }

最直接的"有光源"证明：光源的位置是可以被质疑的，所以它必须能移动。 代价是它只在有鼠标的设备上成立 —— 手机上什么都不会发生，这条得有静态兜底。 另外别让它跟得太紧，1:1 跟随像贴纸；下面 E 里那个阻尼版本才像光。

E · 阻尼跟随 + 抬起 lerp 0.08 · hover 抬 4px ← 同样移上去，感受差别
cur += (target - cur) * 0.08; /* 每帧追一点点，不是直接赋值 */ .media-lift { transition: transform .5s var(--ease), box-shadow .5s var(--ease); } .stage:hover .media-lift { transform: translateY(-4px); /* 纸被抬高，影子跟着变软变大 */ box-shadow: 0 2px 4px rgba(60,50,40,.05), 0 18px 44px rgba(60,50,40,.09), 0 40px 80px rgba(60,50,40,.06); }

这个是我推荐的。阻尼让光有质量 —— 它追你，但追不上。 再加上"纸被抬起、影子变软变大"，两件事说的是同一个物理事实，所以不显得是两个特效叠在一起。 整个交互只有 4px 的位移，但因为影子同时在变，读起来的幅度比 4px 大得多。

F · 随滚动漂移 光晕位移 = 滚动量 × 0.06 ← 滚动页面时它在动
/* 光晕比内容慢 —— 视差，但只给背景用，内容不许动 */ bloom.style.transform = 'translateY(' + (offsetFromCenter * 0.06) + 'px)';

好处是触屏也成立，不依赖鼠标。坏处是系数一大就晕，而且它和你刚做的 scroll reveal 抢同一份注意力。两个都要就都调弱，或者干脆只留一个。

G · 光扫过 她的 tmSweep，换成影子 16s 一轮，含 30% 静止
@keyframes sweep { 0% { transform: translateX(-130%); } 70% { transform: translateX(150%); } 100% { transform: translateX(150%); } /* 停 30% —— 不是匀速循环 */ } .sweep { width: 22%; background: linear-gradient(90deg, transparent, rgba(120,105,85,.055) 50%, transparent); animation: sweep 16s ease-in-out infinite; }

最接近她原作的一条，只是白色高光换成了 5.5% 的暖影。 那个 30% 的静止是关键 —— 匀速循环会读成"加载中"，停顿才读成"光偶尔晃了一下"。 但说实话：它不响应你，只是自己在动。你说想要 interactive，那 D/E 才是，这条是氛围。

结论

底子用 A + B —— 页面退一档、媒体变纯白加三层影子。这两处恰好一起解决了你图片"发糊"的老问题， 而且改的是 token 和 .img-block，全站 case study 一起变。

交互用 E。阻尼跟随 + 悬停抬起，两件事讲同一个物理事实，不像堆特效。

C 只给 hero（正文图溶边会吃掉内容）。顶边高光和 G 可以不要 —— G 好看但不响应你，而且会跟你刚加的 scroll reveal 抢注意力。

还有一条不在选项里但更重要：光晕不要每张图都加。一个页面只能有一个光源， 加满了就退回成材质，反而什么都不剩。
